# Silver Labels: How This Project Labels Data (and Why "Accuracy" Is the Wrong Word)

## What "silver labels" means here

Every label in this repository — `data/labeled/silver_standard.jsonl` and
`data/labeled/silver_standard_crossval.jsonl` — was generated by an LLM
(`gpt-4o-mini`) running one of the prompt templates. **No human labeling was
performed** for these files. (A human-labeling CLI exists at
`src/labeling/label_reviews.py` and would write `gold_standard.jsonl`, but it
has never been run; that file does not exist.)

Consequences:

- Metrics against these labels are **agreement with an LLM labeler**, not
  accuracy against ground truth.
- Agreement between two LLM prompts is inflated by shared biases: same model,
  same schema, similar instructions. Treat absolute numbers as optimistic.
- `confidence` fields stored in label files are hard-coded constants (0.85 /
  0.90), not calibrated probabilities.

## The self-testing problem

The first experiment grid (`run_experiments.py --generate-silver --prompt v5`
followed by `--run-all`) evaluated every prompt against labels produced by v5
itself. Self-testing inflates agreement dramatically: v5.0 k=0 scored
94.3% theme F1, 98% sentiment, 100% risk — against its own outputs. Those
numbers are retained only as a case study of measurement error; they are not
performance results.

## Leave-one-prompt-out (the corrected protocol)

`evaluate_crossval.py` and `src/evaluation/evaluate_prompts.py` now exclude
every label row whose `prompt_version` matches the prompt under evaluation:

```
Reference labels: rows generated by v2, v3, v6
Test v2 -> uses rows from v3, v6 only
Test v3 -> uses rows from v2, v6 only
Test v6 -> uses rows from v2, v3 only
Test v1/v4/v5 -> no own rows exist; all rows used
```

Splits operate on **unique review IDs**, so multiple labels of the same review
never straddle a split, and results report both label-row and unique-review
counts.

## What the corrected numbers are (and are not)

See `data/evaluation/rescored_crossval_summary.json` for the offline
re-scoring of the historical predictions under this protocol, and the README
results table. Caveats that do not go away:

- Still LLM-vs-LLM agreement (silver), not human-ground-truth accuracy.
- Tiny sample: the historical predictions cover 50 label rows over 17 unique
  reviews.
- v1/v4's near-zero theme F1 largely reflects free-form theme vocabularies
  rather than wrong sentiment (their sentiment agreement is far higher).
- Historical predictions, not a fresh run.

## Getting real ground truth (future work)

1. Human-label a stratified sample with `src/labeling/label_reviews.py`
   (writes `labeled_by: 'human'` rows).
2. Spot-check with `src/labeling/verify_labels.py`.
3. Only then report "accuracy" against that file — the evaluator reserves
   that word for human-ground-truth comparisons.
